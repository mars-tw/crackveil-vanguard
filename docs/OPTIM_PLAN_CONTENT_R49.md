# Crackveil Vanguard 內容優化 R49 計畫

基準 `92e858b`（0.77.0-content-r48，已推送、網頁版自動更新）。使用者指示：陽光農場第 85 輪做完後「改做 Crackveil」。依 `game-optimization-round` 八大面向，本輪處理 R44 兩份評審（Claude 8.0、Codex 8.3）在 R45 之後仍未解的項目，並加一段新內容。A、B、C 三線由 Claude 子代理施工，主控整合；本機 GPU 依全域規則留給 H3 產片，截圖一律軟體繪圖。

## A 線：第一次就懂、手機中央少一點字
1. 第一次封隙就教會取捨（R44 Codex 第 2 件）：第一次出現封隙答案時，用一句短句講清「快封：少補血／慢封：多補血／錯陣：反噬」，並顯示這次的即時預估值；之後不再重複。
2. 慢封秒數只有一個來源（R44 Claude 第 3 件）：同一畫面只出現一個慢封秒數；受專精或關卡影響時，旁邊寫小字來源（例「專精＋3 秒」）；「快封楔形」與「1 秒內換成圓陣」同時成立時，頂欄只顯示最優先的一條。
3. 手機戰鬥中央減量（R44 Codex 第 1、3 件）：844×390 戰鬥中，事件、判定字與敵群同時出現時，中央至少 55% 沒有文字面板；名牌＋徽章＋字牌同時最多 3 塊，其餘收進頂欄或縮成圖示；非當前答案降亮度。
4. 封隙判定字不壓齒核基座（R48 未解）。
5. 測試：`scripts/debug/content_r49_test.gd`（單元）＋手機版面量測整合測試；不得放寬既有測試。

## B 線：亂戰中認得出自己與致命攻擊（R44 Codex 第 4 件）
1. 九人隊伍、兩群敵人加大型特效同時出現時，隊長輪廓不得連續 0.5 秒以上完全看不到：加強隊長外框或底圈、降低友方爆炸中心亮度。
2. 致命的敵方攻擊用固定色相＋固定形狀（與一般攻擊分得開），四種攻擊預警在 64px 縮圖仍分得出。
3. 用真實戰鬥（機器人只用觸控／鍵盤輸入）量測並截圖：桌面 1280×720、手機橫式 844×390。
4. 測試：`scripts/debug/combat_readability_r49_test.gd`；亮度與飽和度雙閘門照舊。

## C 線：新內容——無盡模式輪替戰場規則
1. 現在無盡模式只是逐波加數值。改成每隔幾波（例如每 3 波）換上另一關的招牌規則（月華花蕾、潮紋、雷柱、霜牆、齒核等既有規則），頂欄預告下一段是什麼規則、還剩幾波；不新增數值膨脹以外的懲罰。
2. 無盡結算寫出這局遇到哪些規則、各處理得如何，並給一句改法；無盡最佳紀錄照舊保存。
3. 規則套用沿用各關既有程式，不複製一份；手機與桌面都要能讀懂預告。
4. 測試：`scripts/debug/endless_rotation_r49_test.gd`（輪替順序、預告、結算）＋自然機器人無盡局至少兩種規則實際出現的紀錄。
