# R33 戰鬥改版

更新日期：2026-10-02，Asia/Taipei。本頁記錄本機實作與工程驗證；正常遊玩的畫面與節奏評價另由遊戲體驗員回報。

隊長現在會主動斬開近身敵群。移動約 1.15 秒能蓄滿下一次 Space 的拔刀斬；按下 Space 後，角色先拉開出刀姿勢，在攻擊第 2 格打出金白刀刃、青白外緣與短殘影。敵人同時受傷、後退或進入死亡姿勢，範圍內的經驗值接著往隊長回收。

## 這次改了什麼

| 項目 | R32 | R33 |
| --- | --- | --- |
| 隊長自動近身斬 | 無，三組武器自行運作 | 145 距離、115° 扇形、26 基礎傷害，每 0.72 秒最多一斬 |
| Space | 195 距離、76°、30 傷害，3.2 秒冷卻 | 270 距離、138°、72 傷害，2.35 秒冷卻；移動蓄滿後 108 傷害 |
| Space 撞到出刀動畫 | 動畫忙碌時拒絕輸入 | 保留輸入 0.65 秒，收招後開始下一段完整攻擊 |
| 裂線起始傷害與穿透 | 12 傷害、0 穿透 | 20 傷害、1 穿透；原有武器強化照常累加 |
| 裂線節奏 | 0.86 秒、速度 590 | 約 0.65 秒、速度 743.4，換成粗短的金白尖彈 |
| 環繞刀與迴旋鏢 | 帶光暈的金屬貼圖 | 小型青白飛刀、雙彎能量刃；原來的碰撞與折返機制保留 |
| 飛彈與榴彈 | 綠色筒狀貼圖 | 短金白追蹤彈、金殼能量核；追蹤與拋物線照常運作 |
| 普通命中、死亡光效 | 火花貼圖、光暈與煙圈 | 短星芒與方向碎片，普通碎光約 0.22 秒、接觸星芒約 0.15 秒 |
| 多殺提示 | 反覆顯示 CLEAVE／RAMPAGE／SLAUGHTER | 戰場移除這批字樣，保留短弧、音效與命中事件統計 |

自動斬和 Space 共用角色既有的真姿勢動畫。武器不會在按鍵當下傷怪，也不會靠旋轉整張角色圖代替出刀。近身敵人進入扇形後，由第 2 格事件一次結算；收招期間不再結算第二次。大招緩衝同樣要重新走完起手到命中的姿勢。

## 打擊與回收

自動斬命中時，短停頓為 0.018 秒；拔刀斬命中時為 0.045 秒。隊長的震動與停頓入口另有 0.22 秒節流，空揮不觸發停頓。刀光以正常混合的輪廓、刀刃與少量星芒呈現，沒有覆蓋整個扇形的霧光。桌機共用命中特效最多 28 組，手機最多 12 組。

手機橫向實玩發現朝上的大刀只露出兩側，主刀刃出到畫面上方。因此手機刀光以出刀原點為中心，將整組刀刃、殘影與碎光投影為較扁的地板透視；寬度乘 0.84，高度乘 0.504，星芒收近到前方半徑的 0.5。傷害的 270 距離與 138° 扇形維持原值，角色本身也沒有縮放。桌機刀光沿用完整尺寸。

拔刀斬命中後，會呼叫既有的經驗磁吸服務；0.7 秒後再回收一次，接住死亡姿勢結束後才生成的掉落。掉落仍由敵人的死亡流程發出，裝備不會因這項磁吸直接增加，也不會提前跳過敵人死亡姿勢。原有裝備加成、武器強化、進化、羈絆與三槽裝備沿用。

兩種刀聲由音訊服務產生：短促的下行刀風接低頻命中聲；重斬保留較長的低頻尾音。它們使用獨立播放冷卻與既有音量／靜音設定，不需再下載音檔。工程驗證沒有代替真人聽感評分。

## 已執行的驗證

`CombatR33RegressionTest` 已通過，輸出保存在 `docs/evidence/r33/combat/combat_r33_regression.txt`。驗證涵蓋：

- Space 在起手階段不傷怪，第 2 格一次擊倒扇形中的 5 隻普通怪；背後與範圍外的目標保持原 HP。
- 自動斬一次命中，收招期間按 Space 會接下一段攻擊，連按不會重複排入技能。
- 移動蓄滿後造成實際 108 傷害，出刀消耗蓄勢；怪物物件重新使用後不會吃到已結束的斬擊。
- 裂線起始數值為 20 傷害、1 穿透；友方尖彈與敵方投射物保留不同的外觀路徑。
- 90 組斬擊壓力測試仍遵守桌機 28、手機 12 的特效上限；短停頓結束後沒有遺留時間倍率擁有者。

`CombatR32RegressionTest` 與 `TrueAnimationRegressionTest` 也已通過。R13 的舊驗證要求裂線擊退只有 4–8 px；R33 故意增加至約 18–24 px，首輪實測 22.82 px，這項舊規格已交由主整合流程更新並重跑。R10.5 的舊 3.2 秒技能冷卻驗證同樣需要跟著改為 2.35 秒。

以上確認的是傷害、輸入、碰撞、動畫事件與效能上限。遊戲是否夠有力，仍要看正常移動下能否持續接到怪群、刀光有沒有擋住危險提示，以及第一分鐘的清怪和拾裝節奏；不可把這些測試的 PASS 直接寫成爽度評分。

## 給整合與體驗員的讀取接口

`GameManager.player.get_cleave_debug_state()` 回傳 `auto_cuts`、`auto_hits`、`active_hits`、`kills`、`last_hits`、`last_kills`、`max_hits`、`momentum` 及等待出刀的狀態。這是讀取證據用的接口，不會替玩家增加裝備、經驗或傷害。

傷害統計以 `rift_captain:captain_blade` 記錄，並區分 `auto_cut` 與 `draw_cut`。要單獨驗證舊武器，可把測試英雄的 `auto_cleave_cooldown_timer` 設為 999，避免新增的近身斬混入武器測試。
