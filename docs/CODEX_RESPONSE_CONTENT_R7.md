## 二進位：正式版清理（依 MUSE 稽核）

MUSE 結論：裂隙先鋒與帳號內其他款沒有相同的自有程式或出貨素材檔案（只有 OFL 授權文字、MIT 範本、Kenney CC0 原始素材等第三方標準檔相同）；最具體的問題是正式版夾帶測試／QA 程式。本輪處理：

- **QA 程式移出手機版**：網頁探針（`cv_r19_test`／`cv_r22_test` 與 `window.__cvR*`）、HUD 執行期探針（`cv_r32_test`）、世界地圖探針、QA 存檔分流（`CV_QA_PROFILE`）全部搬到 `scripts/qa/`。遊戲只透過 `scripts/services/qa_bridge.gd` 呼叫；該資料夾不存在時（手機版）每個呼叫都不做事。iOS 與兩個 Android 匯出設定排除 `scripts/qa/**`，所以這些程式與參數名稱不在手機版二進位內。網頁版保留，因為本專案的自動化 Web 檢查要用；Apple 不會收到網頁版。
- **美術探針四支**（`r33_art_probe` 等）從 `scripts/arena/` 移到已被排除的 `scripts/debug/`，與其場景同處。
- **測試用裝置覆寫**（`set_device_hints_override_for_tests`、強制手機 LOD）只在除錯建置生效；正式建置不會被它影響。
- **手機版排除清單補齊**：`release/**`（舊驗證紀錄曾被打包）、`native/**`、`output/**`、`.playwright-cli/**`、`.github/**`、`web/*.html|js|mjs`。
- **新增守門測試**：正式程式中出現上述測試開關名稱即失敗；三個手機版匯出設定必須排除 `scripts/qa/**`、`scripts/debug/**`、`release/**`。

未處理、需要另外決定或另外驗證：
- 七期（同帳號另一款 Godot App）與本作共用 iOS 打包流程；兩款乾淨匯出後的 PCK 檔案差異表尚未做（七期原始碼不在本輪範圍）。
- `native-kit` 的 iOS 驗證腳本與舊來源紀錄的 build 號（1）和目前設定（3）不一致；送審前要以同一份來源重產。

- 手機版的實際 PCK 內容清單需要乾淨匯出 iOS／Android 後讀回確認；本輪只做了設定與原始碼層檢查。
