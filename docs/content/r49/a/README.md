# R49 首次封隙與手機戰場

新存檔第一次看到封隙時，頂欄會用五秒說明當前兩種陣形的補血量，以及錯陣會讓進度歸零。教學跟著進度儲存。封隙整備會把兩陣補血都顯示為零。封隙時間來自同一套規則，專精改變時間時會標明差值。有齒核、潮紋或花蕾要處理時，頂欄優先顯示該關動作。

手機橫式把陣形比較放進頂欄，地上保留指向當前答案的圖示。菁英名牌同時至多一塊。近遠基座用一刻、兩刻識別，倒數跟著頂欄；封隙判定會避開兩個基座。桌面仍保有完整的答案牌。這批改動調整顯示與教學，補血量與陣形規則沿用遊戲原值。

## 實測

- Godot 4.7.2 新測試 `CV_QA_PROFILE=content_r49 godot --headless --fixed-fps 60 --path . --script res://scripts/debug/content_r49_test.gd` 通過 14 項。使用實際競技場確認首次顯示、存檔重讀、專精數值、潮紋優先及判定避讓兩個基座。
- 受影響的舊回歸 R11、R13～R19、R39、R40、R43～R45、R47、R48 全部通過。R11、R44 的原始碼驗證更新為檢查實際保留的文字範圍，以及預留前先避讓障礙物的順序。原來直接比對的固定 280×58 已由手機單行、桌面雙行的實際尺寸取代。
- GitHub Actions 的 Chromium 以 SwiftShader 和觸控模擬進入時輪工坊。五個 844×390 取樣中，中央區域至少有 95.76% 沒有文字面板，同時最多兩塊文字牌。五次均有近、遠基座，封隙判定與基座零重疊。測量 JSON 和兩張原圖已換成本次雲端結果。
- 重跑瀏覽器量測時，先依 R48 Web 流程匯出並以本機 HTTP 提供，設定 `CV_R49_URL`，執行 `node tools/r49_phone_layout.cjs`。每次測量會建新的瀏覽器環境。驗證門檻為 55%、最多三塊、基座零重疊，且須拍到首次教學與競技場實況。這是瀏覽器手機模擬。
- 清除了本次 Web 匯出與暫存檢查紀錄，共 111,461,406 位元組。保留測試、正式截圖、量測 JSON 與這份說明。
